# Docs

Start here: read `concept.md` (what we're building), then `devpost.md` (what we're judged on).

| File | What it's for | Update when |
|---|---|---|
| `concept.md` | The chosen idea (Twitchy — Stream Shield), how it works, scope, demo outline, rejected ideas | Scope changes |
| `devpost.md` | Copy of the Devpost page: brief, submission requirements, prizes, judging criteria | Devpost posts an update |
| `codex-sessions.md` | Each teammate's Codex session ID and area; marks the main thread whose ID goes in the submission | Someone starts a new Codex thread |
| `architecture.md` | Components, Twitch APIs/EventSub used, data flow (not written yet) | Tech decisions change |

## Rules
- Codex is the main builder; most work happens in one Codex thread. Its session ID (from `/status`) goes in the submission; keep `codex-sessions.md` current.
- Commit and push often; merge at least daily.
- If a decision changes, update the doc in the same commit.
